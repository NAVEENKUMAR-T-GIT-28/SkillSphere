📊 2.4 Readiness Score Engine
Placement Readiness Score =
(Verified Skills × 0.20) + (Certifications × 0.20) + (Projects × 0.25) +
(ATS Score × 0.15) + (Coding Performance × 0.15) + (Faculty Assessment × 0.05)
Skills (20pts)
Verified countbase score
Category diversity+bonus for spread
Proficiency levelsExpert weighs 4×
Endorsements+weight multiplier
Trending skills+demand bonus
Certifications (20pts)
Verified countbase score
Issuer tierTier1 (Google/AWS) = 3×
Recency<1yr full, <2yr 0.8×
CategoryTechnical > Soft Skills
Relevance to drives+bonus if in JD keywords
Projects (25pts)
Complexity tierAdvanced=full, Basic=0.4×
Faculty rating5-point rubric avg
GitHub activitycommits, stars, last active
Deployed vs prototypelive demo +bonus
Featured project+visibility bonus
ATS Score (15pts)
Keyword densityvs top 50 drive skills
Formatting scoresection structure
Action verbsNLP detection
Quantified achievementsnumber detection
Latest version onlynormalized to 15pts
Coding (15pts)
Problems solvedacross all platforms
Difficulty mixHard=3×, Med=2×, Easy=1×
Contest ratingCF/CC/LC percentile
GitHub contributionsstreak + commit count
Badges earnedplatform achievements
Faculty (5pts)
Avg faculty ratingall evaluations
Endorsement countacross all skills
Assessment commentsqualitative weight
Trigger eventsre-calc on any change
READINESS TIER CLASSIFICATION
🏆 Industry Ready85 – 100Exceptional profile. Prioritize for premium drives. Recommend leadership roles and research opportunities.
✅ Placement Ready65 – 84Strong candidate for most drives. Minor skill/resume gaps. Flag for targeted drives immediately.
📈 Developing40 – 64Foundational skills present. Needs project depth and certifications. Faculty mentoring recommended.
⚠ Beginner0 – 39Critical intervention needed. Alert HOD. Assign faculty mentor. Create 90-day improvement plan.
Recalculation Triggers: Score is recalculated synchronously on: skill verified, cert verified, project rated, resume uploaded (async ATS score arrives), coding sync complete, faculty assessment added. Each recalculation writes a new ReadinessScoreHistory entry.

⚡ 3.6 Redis Caching Strategy
session:{user_id}8 hoursJWT metadata — role, dept, last_active. Invalidated on logout or role change.
jwt:blacklist:{jti}Until expRevoked tokens. Checked on every request to catch forced logouts.
rate:{ip}:{window}1 minuteRate limit counter per IP/user. INCR with EXPIRE. Sliding window.
leaderboard:{batch}:{section}15 minutesSorted set (ZSET) of student_id:coding_score. ZREVRANGE for top-10. Updated on each coding sync.
score:{student_id}5 minutesCached readiness score + breakdown. Invalidated immediately on any score-triggering event.
dashboard:hod:{dept_id}10 minutesHOD executive KPIs (avg score, tier distribution, pending verifications). Expensive aggregation.
search:filter:{hash}2 minutesCached search results keyed by filter hash. Invalidated on any student data change.

🔗 Service Dependency Map
readinessScore.service→ readsSkills, Certificates, Resumes, Projects, CodingProfiles, Faculty ratings → Student
atsEngine.service→ readsResume file (via storage.service + S3) → writes Resume.ats_score → triggers readinessScore.service
verification.service→ writesVerificationLog (append-only) → updates Skill/Cert/Project status → triggers readinessScore.service → notification.service
codingSync.service→ callsAll 6 integration files → writes CodingProfiles → triggers readinessScore.service
placement.service→ readsStudent (score, cgpa, skills) + PlacementDrive.eligibility_rules → writes Applications → notification.service
search.service→ queriesElasticsearch (students_index) + Redis cache → returns ranked Student list
report.service→ readsMongoDB aggregations → Chart.js → Puppeteer PDF → storage.service (S3) → email.service
notification.service→ writesNotification (MongoDB) → Bull Queue → notificationDispatch.job → email.service + FCM
auth.service→ writesUser (last_login, failed_count) → Redis (session, JWT blacklist) → VerificationLog (login event)
ocr.service→ called byCertificate upload flow → Tesseract/Textract → updates Certificate.ocr_extracted
storage.service→ used byCertificate, Resume, Project, Photo uploads → S3 put/get/presign/delete
certExpiry.job→ readsCertificate (expiry_date index) → marks EXPIRED → notification.service (30d/7d alerts)
slaEscalation.job→ readsVerificationLog (PENDING items with age >48h) → notification.service → HOD alert
